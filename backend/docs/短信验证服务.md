# 短信验证服务

## 概述

OpenRD 使用阿里云号码认证服务（PNVS）的 `SendSmsVerifyCode` 接口实现短信验证码功能，用于用户注册和密码重置场景。

## 服务商信息

| 项目 | 值 |
|------|-----|
| 服务 | 阿里云号码认证服务 (PNVS) |
| API | SendSmsVerifyCode |
| SDK | `alibabacloud-dypnsapi20170525` v2.0.0 |
| Endpoint | `dypnsapi.aliyuncs.com` |
| 控制台 | https://dypns.console.aliyun.com |
| 文档 | https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-sendsmsverifycode |

## 签名与模板

使用阿里云号码认证控制台 **赠送** 的签名和模板（非自定义），运营商管控严格，自定义签名容易下发失败。

- 签名管理：https://dypns.console.aliyun.com/smsCertParamsConfig/sign
- 模板管理：https://dypns.console.aliyun.com/smsCertParamsConfig/template

赠送模板格式示例：

```
您的验证码是${code}，有效期${min}分钟，请勿告诉他人。
```

模板变量：
- `${code}` — 验证码（由 API 自动生成或传入指定值）
- `${min}` — 有效期分钟数

## 业务流程

### 发送验证码

1. 客户端请求 `POST /api/v1/auth/sms-code`，传入手机号和场景
2. 检查 Redis 冷却 key `sms_cooldown:{phone}` 是否存在（防刷）
3. 调用阿里云 `SendSmsVerifyCode` API：
   - `TemplateParam`: `{"code":"##code##","min":"5"}` — 由 API 自动生成验证码
   - `ReturnVerifyCode`: true — 响应中返回生成的验证码
   - `CodeLength`: 6 — 6 位纯数字
   - `CodeType`: 1 — 纯数字
   - `ValidTime`: 300 — 阿里云侧有效期 5 分钟
   - `Interval`: 60 — 阿里云侧频控 60 秒
   - `DuplicatePolicy`: 1 — 覆盖旧验证码
4. 将返回的验证码存入 Redis `sms_code:{scene}:{phone}`，TTL 5 分钟
5. 设置冷却 key `sms_cooldown:{phone}`，TTL 60 秒

### 校验验证码

1. 注册/重置密码接口在业务逻辑中调用 `verify_sms_code()`
2. 从 Redis 读取 `sms_code:{scene}:{phone}` 与用户提交的验证码比对
3. 匹配成功则删除该 key（一次性使用），返回 True
4. 不匹配或不存在返回 False

## Redis Key 设计

| Key | 值 | TTL | 用途 |
|-----|-----|-----|------|
| `sms_cooldown:{phone}` | `"1"` | 60s | 同号码发送频率控制 |
| `sms_code:register:{phone}` | `"701226"` | 300s (5min) | 注册场景验证码 |
| `sms_code:reset_password:{phone}` | `"701226"` | 300s (5min) | 重置密码场景验证码 |

## 环境变量配置

```env
# AccessKey（RAM 用户需有 AliyunDYPNSFullAccess 权限）
SMS_ACCESS_KEY_ID=your-access-key-id
SMS_ACCESS_KEY_SECRET=your-access-key-secret

# 签名名称（使用赠送签名）
SMS_SIGN_NAME=你的签名名称

# 模板 CODE（使用赠送模板）
SMS_TEMPLATE_REGISTER=SMS_00000001
SMS_TEMPLATE_RESET_PASSWORD=SMS_00000001

# 业务参数
SMS_CODE_EXPIRE_MINUTES=5
SMS_CODE_COOLDOWN_SECONDS=60
```

## RAM 权限要求

调用该 API 的 RAM 用户/角色需要授予以下权限策略：

- `AliyunDYPNSFullAccess`（号码认证服务完整权限）

或自定义策略：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "dypns:SendSmsVerifyCode",
      "Resource": "*"
    }
  ]
}
```

## 错误处理

| 错误场景 | 错误信息 | HTTP 状态码 |
|----------|---------|------------|
| 60 秒内重复发送 | 发送过于频繁，请稍后再试 | 400 |
| 模板参数不匹配 | 短信服务异常: ... | 400 |
| RAM 无权限 | 短信服务异常: ... | 400 |
| 手机号格式错误 | 短信服务异常: MOBILE_NUMBER_ILLEGAL | 400 |
| 触发天级流控 | 短信发送失败: ... | 400 |
| 验证码错误/过期 | 验证码错误（由调用方业务逻辑返回） | 400 |

## 安全注意事项

1. **AccessKey 保护**：AccessKey 仅存于 `.env` 文件，不得提交到版本库
2. **频率控制**：双重防刷 — 本地 Redis 60s 冷却 + 阿里云侧 Interval 参数
3. **验证码一次性**：校验成功后立即从 Redis 删除，不可重复使用
4. **有效期**：验证码 5 分钟过期，超时自动失效
5. **覆盖策略**：同场景重复发送时旧验证码失效（DuplicatePolicy=1）
