# OpenRD 后端

`backend/` 是 OpenRD 的后端项目目录。仓库采用单仓库结构，前端和后端分别放在 `frontend/` 与 `backend/` 中。

## 当前状态

后端工程尚未初始化。目前目录中没有：

- 后端运行时或框架配置
- 包管理文件
- API 服务入口
- 数据库 Schema
- 数据迁移
- 鉴权实现
- 测试脚本

因此当前不能在该目录中运行启动、测试、迁移或部署命令。

## 产品依据

后端实现应以正式 PRD 为准：

```text
../docs/OpenRD协作平台PRD正式版.md
```

## 后端核心职责

- 用户注册、登录、忘记密码和会话管理。
- 用户资料、身份、角色和权限管理。
- 需求提交、需求沟通、需求审核、驳回、挂起和转化任务。
- 任务大厅、任务详情、任务认领、队伍成员和队长管理。
- 产品经理对需求和任务的管理能力。
- 超级管理员对用户、角色、权限和系统配置的治理能力。
- 消息通知、未读状态和业务跳转。
- 系统日志、关键操作审计和安全记录。

## 建议优先建模的数据表

正式 PRD 中列出的核心数据表包括：

- `users`：用户表。
- `demands`：需求表。
- `tasks`：任务表。
- `task_members`：任务成员表。
- `roles`：角色表。
- `permissions`：权限表。
- `role_permissions`：角色权限关联表。
- `system_logs`：系统日志表。
- `demand_replies`：需求回复表。

## 后端初始化前需要确定

- 后端语言、运行时和框架。
- 数据库类型和迁移工具。
- API 风格和接口文档格式。
- 密码加密方案，PRD 要求使用 bcrypt。
- 鉴权方式，例如 Session、JWT 或混合模式。
- 角色权限模型和权限命名规范。
- 附件上传和存储方案。
- 操作日志、安全审计和异常监控方案。
- 测试框架和接口测试规范。

## 建议首个里程碑

第一阶段建议先完成：

1. 应用配置和健康检查接口。
2. 用户、角色、权限基础模型。
3. 登录鉴权和当前用户接口。
4. 需求、任务、队伍成员的基础模型和迁移。
5. 需求提交到任务转化的最小闭环接口。
6. 系统日志记录机制。

## 与前端的协作边界

后端必须作为权限和状态的事实来源。前端可以做展示级权限控制，但所有接口仍需在后端完成身份校验、权限校验、参数校验和操作日志记录。
