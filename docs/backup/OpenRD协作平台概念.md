# OpenRD协作平台

## 一、共建者准入：新手引导+基础考核

**目标**：筛选有耐心、真正想参与建设的人，避免“随手注册但不贡献”的情况，同时门槛不过高。

**具体流程**：

1. **注册账号后**，进入新手引导流程，完成一套 **50题** 的基础知识考核。
   - 题型分布：45道判断题 + 3道选择题 + 2道主观题
   - 内含若干**注意力检测题**（如明显矛盾的逻辑题），用于判断答题态度

2. **通过标准**：  
   - 完成全部题目，不存在明显胡乱选择（系统可记录答题用时、选项一致性）
   - 主观题表达基本认真即可，不强求专业深度

3. **未通过者**：只能以“游客”身份浏览公开内容，无法参与任务协作、组队等核心功能。

4. **效果**：  
   - 低成本过滤掉浮躁或无意贡献的用户
   - 保持低门槛——只要有心，多数人都能通过
   - 考核过程本身也是对社区严肃性的一次认知建立

## 二、角色分工与组织架构

类似参考文学作品中，冒险者工会的概念，“冒险者工会”的文学概念被转化为一套现实协作逻辑：患者像在工会大厅发布委托一样发布悬赏；不同技术角色（前端、后端、产品等）对应工会里的职业专长；复杂任务需要组队完成，就像讨伐需要坦克与输出配合；平台提供职级晋升和实体/虚拟奖励，类似工会的成长体系；长时间无人认领的任务由官方Khub团队派协调员兜底协助，如同工会会长出面支援。这样一来，去掉奇幻外衣后，工会的本质——需求驱动、角色互补、自由组队、按劳激励、官方兜底——就完整保留在你的协作平台中。

### 1. 协作角色

用户注册后可获得（或选择）以下角色之一，代表其主攻方向：

- **前端开发**
- **后端开发**
- **产品设计**
- **系统运维**
- **软件测试**
- **UI/UX 设计**
- **文档/内容协作**（可选扩展）

后续主角色到一定职称可以开启第二角色，以多个身份加入更多团队

### 2. 角色获取方式

- **推荐机制**：新手引导结束后，通过问卷中的兴趣和技术倾向，系统推荐一个初始角色
- **自行选择**：用户也可在角色列表中自行选择，后续允许变更（设冷却期或审核）

### 3. 职级体系（“职称晋升”）

每个角色内部设置**初级 / 中级 / 高级 / 资深**等级，晋升依据——**实际贡献记录**：

- 完成一定数量的悬赏任务（且任务评价合格）
- 有效的代码/设计/文档提交（PR或合并记录）
- 参与团队协作并完成负责部分
- 获得官方Khub团队或其他资深成员的认可

**晋升激励**（实体+虚拟，保持温度）：
- 实体奖品：患者手写信、纪念拍拍卡、感谢明信片
- 虚拟标识：平台内个人主页显示专属徽章、头衔
- 软权益：优先查看新需求、参与核心共建者讨论会

## 三、任务协作机制（“组队接单”）

### 1. 需求发布（患者侧）

- 患者或需求方发布**悬赏任务**：描述需求、预期完成形式、悬赏积分、建议角色组合

### 2. 任务认领与团队协作

- 平台提供**项目小组板块**：用户可以**创建小组**或**申请加入已有小组**，每个小组需明确成员的角色分工（例如：1前端+1后端+1测试+1产品）
- 小组负责人（或成员共同）**认领悬赏任务**
- 认领后，任务进入“进行中”状态，平台跟踪进度

### 3. 无人认领的任务处理机制

- 若某个悬赏任务**长时间无人认领**：
  - 开放给**未加入小组的自由开发者**个人认领
  - 此时由平台官方 **Khub团队** 派出一名**项目协调员**，负责协助需求拆解、进度跟进和协作管理，确保任务不被搁置

### 4. 项目协调员的职责

- 帮助自由开发者理解需求
- 拆分可执行步骤
- 联络必要的其他角色协助（如临时测试或设计支持）

## 四、积分与激励体系（保持驱动力和人文感）

### 1. 积分获取途径

- **完成任务**：根据任务难度和评价，获得基础积分 + 奖励积分
- **代码/文档贡献**：合并或采纳后获得贡献积分
- **每日签到**：获得少量连续积分，培养日常参与习惯
- **互助行为**：在问答区、任务评价、审阅等环节中给予正面帮助，可获感谢积分

### 2. 积分兑换（积分商城）

- 数字礼品卡（电商、餐饮等）
- 患者手写信（限量、有故事性的特殊兑换品）
- 平台纪念品（拍拍卡、贴纸、帆布袋等）
- 虚拟特权（如解锁更多小组名额、展示特殊身份标识）

### 3. 人文关怀：每日寄语与签到联动

- **每日签到后**：
  - 系统随机推送一条**其他共建者写的寄语**（可来自历史签到或专门征集的内容）
  - 同时邀请用户也写一句自己的寄语（可以是对患者的鼓励、对协作伙伴的感谢、个人心情感悟等）
- **寄语库建设**：
  - 初始可由官方团队和早期共建者提供
  - 用户写下的优质寄语经审核后加入库中，形成正向循环
- **效果**：  
  - 增强平台的情感联结，避免冷冰冰的任务协作氛围  
  - 让共建者感受到“我们是为真实患者和真实需求共同努力”

## 五、方案总结

| 模块      | 核心设计                             | 解决的问题                               |
| --------- | ------------------------------------ | ---------------------------------------- |
| 准入条件  | 50题考核（含注意力检测）             | 平衡门槛与诚意，过滤掉白嫖心态           |
| 角色分工  | 明确的技术角色 + 问卷推荐/自选       | 让每个人知道自己的主攻方向，便于协作     |
| 任务协作  | 小组认领 + 自由开发者+官方协调员兜底 | 既鼓励团队协作，也避免任务无人问津       |
| 职级晋升  | 基于贡献的等级 + 实体/虚拟激励       | 长期激励，不依赖单一积分                 |
| 积分+人文 | 任务积分 + 每日签到 + 寄语推送       | 驱动日常参与的同时，塑造温暖社区的认同感 |
