## 三、注册时收集角色的设计（不突兀）

注册流程中，在填写完手机/邮箱、密码后，增加一个步骤，用**两个温和的卡片**询问：

> **你希望如何参与平台？（可多选）**
>
> 📝 **提出需求** – 我或家人面临罕见病，希望寻求解决方案  
> 💻 **参与开发** – 我是技术人员，希望帮助实现需求

- 只选“提出需求” → 角色：**需求者**
- 只选“参与开发” → 角色：**开发者**
- 两项都选 → 角色：**开发者**（因为开发者已包含发需求能力，无需重复）
- 都不选 → 角色：**需求者**（默认）

这样用户无需理解“角色”概念，按自己的意愿选择即可，自然完成角色分配。

| **目标**     | 维护平台内容，编辑、关闭或删除不合适的需求/工单              |
| **前置条件** | 已登录，拥有运营管理员权限                                   |
| **主流程**   | 1. 运营进入 **“需求管理”** 页面（全量需求列表），支持按状态、提交人筛选。<br /> 2. 找到某个已转化但长期无开发者的需求，点击 **“编辑”**，修改标题或补充信息。<br /> 3. 或找到某个低质量需求，点击 **“删除”**（需二次确认）。<br /> 4. 类似操作在 **“任务管理”** 页面进行：可关闭超时未完成的工单，或重新打开。 |
| **异常分支** | - 删除需求时若已关联任务，系统提示“该需求已转化为任务，是否同时删除？”→ 运营选择确认或取消。 |

### 四、超级管理员（Super Admin）

#### 场景 1：将普通用户提升为运营管理员

| 项目         | 内容                                                         |
| :----------- | :----------------------------------------------------------- |
| **角色**     | 超级管理员                                                   |
| **目标**     | 赋予可信用户运营管理权限，分担审核工作                       |
| **前置条件** | 超级管理员已登录；存在至少一个普通注册用户                   |
| **主流程**   | 1. 超管进入 **“用户管理”** 页面，展示所有用户列表。 <br />2. 搜索或找到目标用户（例如某活跃开发者），点击 **“编辑角色”**。<br /> 3. 弹窗中勾选“运营管理员”角色，点击保存。<br /> 4. 系统更新用户角色数组，该用户下次登录后即可看到运营管理界面。 |
| **异常分支** | - 若尝试移除最后一个超管 → 系统提示“至少保留一个超级管理员”。<br /> - 若用户已是超管，可降级为普通用户（需二次确认）。 |

#### 场景 2：查看审计日志并配置角色权限

| 项目         | 内容                                                         |
| :----------- | :----------------------------------------------------------- |
| **角色**     | 超级管理员                                                   |
| **目标**     | 监控敏感操作（如删除需求、转化任务），并调整不同角色的菜单权限 |
| **前置条件** | 超管已登录                                                   |
| **主流程**   | 1. 超管点击磁贴 **“系统日志”**，进入日志页面。 <br />2. 筛选条件：操作类型（审核、转化、删除）、时间范围、操作用户。<br /> 3. 查看日志列表，发现异常操作（如某运营批量删除需求），点击详情。<br /> 4. 另进入 **“角色管理”** 页面，选择“运营管理员”角色，勾选或取消菜单权限（如取消“删除需求”权限），保存即生效。 |
| **异常分支** | - 日志过多时，支持导出CSV。<br /> - 角色权限修改后，已登录用户需重新登录才生效（前端可提示）。 |
