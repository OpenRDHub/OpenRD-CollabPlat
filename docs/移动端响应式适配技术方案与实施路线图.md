# OpenRD 移动端响应式适配技术方案与实施路线图

## 1. 文档信息

- 文档状态：实施中
- 更新时间：2026-10-07
- 目标分支：`codex/mobile-responsive`
- 当前 Pull Request：[#61](https://github.com/OpenRDHub/OpenRD-CollabPlat/pull/61)
- 适用范围：`frontend/` 中的用户端、认证端、后台管理端及共享 UI 组件

## 2. 背景与目标

OpenRD 前端最初以桌面端布局为主，部分页面存在固定宽度表格、多栏内容、桌面导航和大尺寸弹窗。直接在手机浏览器中使用时，可能出现横向滚动、按钮遮挡、弹窗超出视口、文字截断、安全区未覆盖以及触控区域过小等问题。

本次改造的目标不是单纯缩小桌面页面，而是建立完整的响应式交互体系，使核心业务在手机、平板和桌面设备上都具备可用、清晰且一致的操作路径。

目标验收视口如下：

| 设备类型 | 视口尺寸 | 主要用途 |
|---|---:|---|
| 小屏手机 | 375×667 | 检查最紧凑场景、纵向空间和软键盘风险 |
| 主流手机 | 390×844 | 主要移动端验收基线 |
| 大屏手机 | 430×932 | 检查宽屏手机的内容密度 |
| 平板 | 768×1024 | 检查断点切换和弹窗布局 |
| 桌面 | 1440×900 或同等级尺寸 | 回归桌面端布局和功能 |

## 3. 技术原则

### 3.1 移动优先的信息重排

- 不依赖整体页面横向滚动完成核心操作。
- 关键业务表格在手机端优先重排为信息卡片。
- 无法合理卡片化的高密度治理表格使用局部、可控的横向滚动。
- 筛选器在手机端改为单列或可折叠布局。
- 主要操作按钮保持可见，并避免与系统安全区重叠。

### 3.2 统一响应式能力

- 使用全局间距、触控目标和安全区变量。
- 最小触控区域以 `44px` 为基线。
- 使用 `100dvh` 处理移动浏览器动态地址栏。
- 使用 `env(safe-area-inset-bottom)` 处理底部安全区。
- 共享导航、侧栏、弹窗、分页、输入框和 Toast 统一实现移动规则。

### 3.3 保持业务契约不变

- 响应式改造不改变接口路径、数据结构和权限规则。
- 保留最新 `develop` 中的返回导航、消息撤回、未读统计等业务契约。
- 页面结构调整后继续使用现有 API 和状态管理逻辑。
- 移动端与桌面端必须操作同一份真实业务数据。

## 4. 分期实施计划

整体建议分为五期。目前前两期已基本完成，剩余三期。

### 第一期：响应式基础设施

状态：已完成。

主要内容：

- 建立页面边距、触控目标、动态视口和安全区变量。
- 适配共享顶部导航和应用侧栏。
- 优化按钮、输入框、下拉框、分页、表格、弹窗和 Toast。
- 完成大厅、需求详情、任务详情和团队详情等核心页面适配。
- 建立首批响应式契约测试。

### 第二期：用户端核心页面

状态：已完成开发，集中在 PR #61 中等待审查和合并。

主要内容：

- “我的任务”和“我的需求”在手机端由桌面表格重排为字段卡片。
- 消息分类改为横向滚动，消息操作区改为触控友好布局。
- 消息详情抽屉使用动态视口并锁定背景滚动。
- 个人资料和编辑弹窗适配小屏、滚动区域及底部保存操作区。
- 登录、注册和找回密码适配动态视口与底部安全区。
- 统一“我的需求”页面的共享移动导航。
- 增加 `/api/v1/me/stats` 鉴权与统计逻辑的后端测试。

### 第三期：后台管理页面

状态：待实施。预计占剩余工作量约 50%。

页面范围：

- 需求管理
- 任务管理
- 用户管理
- 权限管理
- 系统日志

实施重点：

- 需求和任务管理优先采用卡片列表，保留状态、负责人和主要操作。
- 用户和权限管理保留高密度字段时，使用局部横向滚动和固定操作列。
- 系统日志在手机端突出时间、操作者、模块、风险和结果，详细上下文放入抽屉。
- 筛选区域采用纵向布局或折叠面板。
- 编辑、授权和确认弹窗采用底部抽屉，操作区保持在安全区之上。
- 危险操作保持明确的二次确认和权限提示。

建议将第三期拆为两个独立交付批次：

1. 需求管理与任务管理。
2. 用户管理、权限管理与系统日志。

### 第四期：交互与边缘场景

状态：待实施。预计占剩余工作量约 25%。

主要内容：

- 软键盘打开后的输入框聚焦、滚动定位和按钮可达性。
- 侧栏开关、遮罩关闭、返回操作和浏览器历史行为。
- 弹窗、抽屉和确认框的关闭、滚动锁定及焦点管理。
- 长标题、长英文、长 ID、空数据、加载失败和权限不足场景。
- 横竖屏切换、窄屏设备和底部安全区。
- 触控反馈、禁用状态及连续点击保护。
- 403、404、Onboarding 等辅助页面的移动端一致性。

### 第五期：全量验收与合并收尾

状态：待实施。预计占剩余工作量约 25%。

主要内容：

- 对全部核心路由执行五组视口验收。
- 检查横向滚动、按钮遮挡、弹窗超屏、文字截断和安全区。
- 对侧栏、遮罩、返回、表单、弹窗和软键盘场景执行交互验收。
- 扩充响应式契约测试和浏览器级核心路由检查。
- 运行类型检查、生产构建、前端契约测试和原有回归测试。
- 与真实后端进行关键接口联调。
- 同步最新 `develop`，处理冲突并确认最终差异仅包含目标范围。

## 5. 页面适配策略

| 页面类型 | 手机端策略 | 平板策略 | 桌面策略 |
|---|---|---|---|
| 普通列表 | 信息卡片、完整主操作 | 单列或双列卡片 | 表格或高密度列表 |
| 管理表格 | 卡片或局部横向滚动 | 视字段数量决定 | 完整表格 |
| 筛选栏 | 单列、折叠或横向分段 | 两列布局 | 单行工具栏 |
| 详情页 | 单列信息流 | 单列或窄双栏 | 双栏或多栏 |
| 普通弹窗 | 底部抽屉 | 居中弹窗 | 居中弹窗 |
| 长表单弹窗 | 可滚动抽屉、固定操作区 | 可滚动居中弹窗 | 居中弹窗 |
| 消息详情 | 全屏抽屉 | 侧边抽屉 | 侧边抽屉 |

## 6. 验收标准

每一期合并前至少满足以下条件：

### 6.1 视觉验收

- 页面根节点不产生非预期横向滚动。
- 导航、标题、筛选器和主要操作不互相遮挡。
- 弹窗和抽屉不超出可视区域。
- 长文本可以换行、截断或在受控区域内滚动。
- 固定按钮和底部操作区避开安全区。
- 手机端卡片字段顺序符合业务阅读优先级。

### 6.2 交互验收

- 移动导航可以打开，并可通过遮罩或操作完成关闭。
- 返回按钮遵循来源路由、浏览器历史和角色回退规则。
- 表单输入、校验、提交和错误提示均可操作。
- 软键盘出现时，当前输入框和提交按钮仍可到达。
- 弹窗关闭后恢复页面滚动和焦点。
- 所有关键触控目标达到约 `44px`。

### 6.3 工程验证

前端最低验证命令：

```powershell
cd frontend
npm run type-check
npm run build
npm run test:contract
npm run test:responsive
npm run test:bundle-contract
```

后端相关改动最低验证命令：

```powershell
cd backend
uv run pytest tests/test_stats.py -q
```

若本地缺少后端运行时或测试数据库，必须在 PR 验证说明中明确标记未运行项目，并以 CI 结果作为最终依据。

### 7.2 已识别风险

- 后台页面字段多，卡片化可能降低跨记录比较效率，需要按业务场景选择卡片或横向滚动。
- 多人并行开发可能频繁修改共享导航和契约测试，合并时必须保留双方逻辑，不能直接拼接冲突内容。
- Mock 数据覆盖不完整会制造浏览器控制台错误，干扰响应式回归判断。
- 仅依赖静态 CSS 契约无法发现按钮遮挡和弹窗超屏，必须保留真实浏览器验收。
- 生产接口依赖 Bearer Token，移动端改造不能绕过鉴权或用本地状态替代后端数据。

## 8. 合并策略

- 每一期使用独立提交或独立 PR，避免一次审查所有后台页面。
- 合并前先获取最新 `develop`，再执行 rebase 或受控合并。
- 发生共享组件冲突时，先理解双方业务意图，再合并模板和脚本。
- 禁止保留重复 JSON 键、冲突标记、重复模板节点或未闭合标签。
- 更新远端历史时使用 `git push --force-with-lease`，避免覆盖他人新增提交。
- CI 全绿后仍需满足仓库的人工审查要求。
